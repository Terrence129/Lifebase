# ADR-016：聊天图谱与 Harness 就绪接口

- 状态：Accepted，用户于 2026-10-06 批准实施；验收结果见 [当前阶段](../reference.md#2-项目背景与当前阶段)。
- 日期：2026-10-06

## 背景

ChatGPT 和豆包的文件导入、Silver 与证据查询已经打通。用户要求用两条来源推进四层
demo，并选择自动主题提取、本地统计组件 jieba，以及 Lifebase 接口完成后停止的交付边界。
运行时依赖方向延续 [ADR-013](ADR-013-Agent运行时集成边界.md)，项目约束见 [AGENTS.md](../../AGENTS.md)。

## 决策

- **Reuse**：collector、Silver、Evidence、PyArrow 和 DuckDB；canonical v1 / Envelope 不变。
- **Reuse**：jieba 0.42.1 的 TF-IDF 和默认词典，配合通用停用词；消息版本默认最多五个关键词。
- **Build**：Gold 格式 v1 包含来源、会话、消息版本、关键词主题与包含/提及关系。主题是
  算法派生关联，保留 Evidence 和算法版本，不自动判定人物身份、用户计划或现实事实。
- **Build**：快照位于 vault/gold，身份包括输入分区哈希、参数、算法、词典和停用词身份。
  内容排序后原子发布，重复构图复用；当前指针可更新，已有完整快照保持原状。输入或
  提取器变化使当前图谱过期，缺失/损坏/过期数据拒绝查询。
- **Build**：HumanOS 提供固定只读查询和 api_version=1 的 JSON CLI，返回规范化片段、
  图谱路径与证据定位。引用检查不重新运行关键词提取；原有 verify 继续检查 RAW/Silver，
  graph status 检查 Gold。
- **Build**：目的地门禁读取注册来源类型与 collector 策略，兼容无前缀历史来源。
  Gold 身份和主题统计依赖整份快照，因此 cloud 请求要求全部输入来源为 cloud_ok；
  来源筛选不能绕过该条件。redact_before_cloud 在尚无脱敏器时同样拒绝。
- **Integrate（后续）**：本地 DeepSeek Harness 消费 JSON 工具接口；其插件、Profile、
  模型调用和实际外发验证在外部仓库实现。本切片的停止点是 Lifebase 独立验收完成。
- **Defer**：模型生成回答、语义聚类、同义概念融合、Past Me、浏览器 UI 和其他来源。

## 被否方案

- 手动主题词表：用户选择自动提取，首版不要求维护别名。
- 立即用 LLM 提取主题：使图谱验收依赖尚未接入的运行时与模型，超出停止点。
- 新增图数据库、向量库：现有 Parquet/DuckDB 足以验证关键词图谱与证据接口。
- 按结果筛选来源后就允许云端使用：快照身份和主题统计仍包含受限输入的派生信息。
- 接口中直接读取 RAW 或在 Lifebase 内实现 Harness 适配：与 ADR-013 的消费方边界不符。

## 后果

图谱和终端检索能够独立使用，模型环境不影响本阶段验收。jieba 引入词典与默认 IDF
的版本成本；统计关键词不具备语义主题理解，近义词与复杂自然语言条件仍可能漏召回。
查询按快照载入内存，继续采用原型规模假设。目的地声明门禁不是操作系统网络隔离，
不能证明外部调用方真的使用本地模型；这项验证仍属于 Harness 联调。
