# ADR-011：约束门禁与文档防漂移

- 状态：Accepted
- 日期：2026-10-05

## 背景

对照 deepseek-harness 的 Agent 约束方法论（用户桌面提炼稿，2026-10-05）审计本仓库约束体系：单一事实源（[ADR-004](ADR-004-约束单一事实源与Agent友好结构.md)）、分层与决策记录已达标；但方法论最核心的机制——「可机械验证的规则接入一个被执行的门禁」——缺失。CI 只覆盖代码与数据（ruff + pytest），文档约束（红线不复制、链接有效）靠 Agent 自觉，且漂移已经发生：`docs/context.md` §26 有红线的英文拷贝，`tests/fixtures/README.md` 复述红线内容。

## 决策

1. **新增约束门禁测试 `tests/unit/test_constraints.py`**，接入现有 pytest（本地收工校验与 CI 自动执行，不加新 CI job、不加新依赖）：
   - 红线短语扫描：红线特征短语（中英变体）只允许出现在 `AGENTS.md`；白名单显式豁免（README 安全摘要、ADR-003 历史引用），豁免写进门禁、可见可审。
   - 仓库 `.md` 本地链接目标存在（只证存在，不证锚点，门禁 docstring 写明证明边界）。
   - `.gitignore` 按行精确覆盖 `data/` `inbox/` `*.db` `*.parquet` `.env`。
   - `graph/`、`humanos/` 无 `.py` 代码；`vault/` 不 import `graph/`。
2. **`AGENTS.md` §3 每行补「执行门禁」列**，规则与门禁双向互指；新增两行：红线唯一归属、文档链接有效。
3. **`docs/adr/README.md` 补 ADR 骨架**：背景/决策/被否方案/后果；已落地 ADR 用现在时，不残留 spec 语气。
4. **清理已发生的漂移**：`docs/context.md` §26 禁止块改为指针；`tests/fixtures/README.md` 复述改为指针 + 局部契约（fixtures 测试规则保留原位）。
5. **DoD 增补防漂移审计清单**（slop 清单，编辑 `AGENTS.md` / `docs/reference.md` 时逐项过）。
6. **开发与校验一律使用 conda `lifebase` 环境**（用户 2026-10-05 明确要求）：删除项目级 `.venv`（uv 优先使用它而绕过 conda 环境，且其 Python 3.14.4 缺 tzdata）；约束写入 `AGENTS.md` §6，并由 `test_no_project_level_venv` 门禁强制；tzdata 已装入 conda 环境。
7. **reference.md 防膨胀**：当前阶段表按阶段重置（阶段结束时浓缩为历史摘要 + ADR 链接，明细归 ADR 与 git 历史）；待评估灵感一律独立成文（`docs/design/*.md`），reference.md §5 只做索引（doubao 浏览器采集灵感已迁出）；约束写入 `AGENTS.md` 规则 8。

## 被否方案

- **独立门禁脚本 + 新 CI job**：多一套入口与本地命令，收工流程不会自动运行它；pytest 是已有的「被执行的门禁」，直接复用最省机制。
- **第三方链接检查工具（markdown-link-check 等）**：引入 Node 工具链与第三方依赖，触碰「新增第三方依赖须停下询问」的停止条件；stdlib 脚本足够覆盖本地链接。
- **白名单豁免 context.md 的原位漂移**：让复制内容原地保留等于承认复制合法；清理后用指针，门禁保持严格。
- **改写 ADR-004 补门禁细节**：旧 ADR 是历史决策记录，不改写；本 ADR 与它交叉链接。另注：ADR-004 中「若使用 Claude Code 需符号链接 CLAUDE.md」的备注已过时——Claude Code 原生支持 `AGENTS.md`，无需补链接。

## 后果

- 文档约束从此由 pytest 强制：红线复制、断链、gitignore 缺项、跨层代码在本地与 CI 都会被拒绝。
- 门禁边界：链接门禁证明「目标存在」而非锚点精确；短语门禁按中英特征短语匹配，改写措辞可绕过——它防无意识复制，不防刻意规避。
- pyarrow 在 Windows 解析带时区时间戳需要 tzdata（缺失时报 `ArrowInvalid: The zoneinfo module or pytz package must be installed`）；已加入项目依赖（pyproject + uv.lock，仅 Windows 平台安装，用户 2026-10-05 确认）。
- Defer（触发条件已记录）：词数预算（`AGENTS.md` 或 `docs/reference.md` 在结构性防膨胀机制之外仍明显拖累阅读与每轮 token 时）；技能层 `.claude/skills/`（`AGENTS.md` 超过约 150–200 行时把工作流型内容迁出为 skill）；Agent Note 完整生命周期（出现协作者时）。

## 更新（2026-10-05）

CI 首次运行（#17）发现 `test_no_project_level_venv` 在 Linux runner 失败：`uv sync` 默认在仓库内创建 `.venv`。该门禁的意图是约束本地开发机（防止 `.venv` 绕过 conda 环境）；CI 没有 conda，`.venv` 属正常环境。不改门禁，改为让 CI 通过 `UV_PROJECT_ENVIRONMENT` 把 uv 环境放到 runner 临时目录（`$RUNNER_TEMP`，仓库外），使「仓库内无 `.venv`」在本地与 CI 都成立，门禁保持无条件执行。本更新不改变上文决策结论。
