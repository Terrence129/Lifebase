# ADR-002：项目命名

- 状态：Accepted
- 日期：2026-10-05

## 决策

1. 伞形名称 **Lifebase**（用户决定）；Python 包名 `lifebase`，CLI 命令 `lifebase`，仓库目录 `Lifebase/`。
2. 四层保留原名：LifeSync / LifeVault / LifeGraph / HumanOS，映射为子包 `sync/` / `vault/` / `graph/` / `humanos/`，与架构图一一对应。
3. 数据根目录 **`~/Lifebase/`**（原 Context.md §22 约定为 `~/LifeSync/`，2026-10-05 随命名统一改为 `~/Lifebase/`；`inbox/` 与 `vault/` 位于其下）。

## 理由

- 与既有 LifeX 命名族一致；"base" 兼取「基座/基地」与 database 之意，中英皆宜。
- 消除「项目名 = 第一层名」的歧义（原仓库名 lifesync 即 LifeSync 采集层）。
- 子包按层命名，未来独立开源某层时拆分是机械操作。

## 后果

- `docs/context.md` 是原 Context.md 的忠实副本，其中「LifeSync 指整个项目」的表述以本 ADR 为准：伞形名称 = Lifebase，LifeSync = 采集层。
- 2026-10-05 已同步更新 `docs/context.md` 与 OneDrive 原 Context.md：数据路径改为 `~/Lifebase/`，系统级「LifeSync」字样改为 Lifebase（§22、§30、§36），层名用法保持不变；文件顶部新增命名更新说明。
