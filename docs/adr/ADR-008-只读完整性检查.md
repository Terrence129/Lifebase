# ADR-008：只读完整性检查

- 状态：Accepted，用户于 2026-10-05 明确委派实现 verify。
- 日期：2026-10-05

## 决策

1. **Build**：在 LifeSync 层编排 RAW、manifest、Source Registry、Silver 与证据审计，
   通过 `lifebase verify` 提供只读入口；现有 canonical v1 和 Envelope 不变。
2. **Reuse（Python hashlib / zipfile / sqlite3、PyArrow）**：验证内容哈希、ZIP 成员、
   RFC 6901 Pointer、数据库 quick_check、Parquet schema/行数，复用现有依赖。
3. **Build**：跨文件检查归档与导入登记、处理身份、消息上下文/父消息、版本哈希、
   证据指向的规范化记录、原始记录 ID、来源及时间。逐项报告问题，单个损坏文件
   不阻断其他对象的检查；报告只含问题类型、定位与 ID，不含源消息正文。
4. **Reuse（SQLite immutable 只读连接）**：只检查静止的主库。发现 WAL/恢复日志
   就报告需要停止写入后重试，不读取可能遗漏事务的主库，也不创建 SHM 或执行恢复。
5. **Build**：扫描磁盘上全部标准对象与已发布分区，包括未登记产物。未登记对象、
   分区和临时路径作为 warning，不将合法的导入失败状态当成数据损坏。
6. **Integrate**：本轮无外部服务。
7. **Defer**：修复、清理、重建、备份，以及并发写入期间的一致性审计。

## 输出与边界

- JSON 包含 `status`、`counts`、`issues`；每个问题提供 `code`、相对路径、说明、
  严重程度，以及可选的 evidence ID。发现 error 或 warning 都返回退出码 1。
- counts 统计发现的标准对象、归档条目、分区及已读取检查的证据行；损坏分区的
  证据可能无法读取，其 evidence 计数不代表整个仓库的预期数量。
- 不存在的目录视为空库，不创建目录或索引。不沿仓库内的符号链接读取目标。
- 证据读取保留与现有 collector 一致的 JSON 成员大小上限，ZIP 从不解压到磁盘。
- 本次审计验证存储完整性和引用一致性，不重新执行全部 parser 映射，也不能证明
  官方格式覆盖率。更改后的完整一致数据不能凭自存哈希证明其真实性。
- 不写入数据目录，内容、mtime、权限与文件清单保持不变；OS 的 atime 更新除外。
  对不支持的 schema 版本报告失败，后续版本需扩展检查器。

## 验收

合成测试覆盖健康与重叠导出、空库、RAW/Silver 缺失及损坏、证据定位与成员哈希、
没有证据的记录、上下文关联、数据库损坏、WAL、未登记产物和符号链接。
健康及故障检查前后均对比文件内容、mtime、权限和目录清单，CLI 验证退出码与 JSON。
