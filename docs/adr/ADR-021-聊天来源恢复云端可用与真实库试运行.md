# ADR-021：聊天来源恢复云端可用与真实库试运行

- 状态：Accepted，用户于 2026-10-21 批准；取代 [ADR-020](ADR-020-Harness联调与合成库云端放行.md) 中「来源策略」一条与「真实库在 cloud 下拒绝」的结论。
- 日期：2026-10-21

## 背景

ADR-020 把 `chatgpt` 与 `doubao` 的默认外发级别恢复为 `local_only`，真实库只能在本地使用，
Harness 联调只用合成库。合成库联调已通过，下一步是在真实库上试运行。真实库内容是用户与
ChatGPT、豆包的对话，来源本来就在云端服务商处。用户判断这类数据继续交给云端模型的风险可以接受，
并批准真实库使用云端模型回答。项目约束见 [AGENTS.md](../../AGENTS.md)，其中用户最新指示优先于红线。

## 决策

- **Build（来源策略）**：`chatgpt` 与 `doubao` collector 的默认外发级别改为 `cloud_ok`，
  取代 ADR-020 的同名决策。三级框架（ADR-012）与「cloud 要求整份图谱的输入来源全部为
  `cloud_ok`、来源筛选不能绕过」的门禁逻辑不变。
- **范围**：只放宽这两个来源类型。以后新增的来源（如微信）按 ADR-012 默认 `local_only`，
  由各自的 ADR 决定。
- **Integrate（目的地）**：批准的云端目的地仅限 DeepSeek 官方 API，由 Harness 插件的 provider
  映射判定（ADR-020）。其他 provider 如需使用，须另行批准。
- **保留**：合成 fixture 哈希白名单与 ADR-020 的独占工具 guard 不变。白名单在来源策略为
  `local_only` 时仍是合成库走云端的唯一通道；guard 继续限制模型只能经 Lifebase 工具取数。
  每次工具调用只返回命中的片段，不上传整个库。
- **Defer**：本地模型路由、脱敏器（`redact_before_cloud`）、会话列表工具、模型回答的 Gold 保存。

## 被否方案

- 保持 `local_only` 并等本地模型路由：本地模型尚未实现，试运行会被无限推迟。
- 只放行指定会话或时间范围：门禁按整份图谱判断，来源筛选不能缩小外发依赖，
  需要新的分区与策略机制，现阶段复杂度过高。
- 删除合成白名单：放宽后白名单不起作用，但保留它没有代价，也为来源改回 `local_only` 留有后路。

## 后果

- 收益：真实库可以通过 Harness 由云端模型回答，开始真实数据试运行。
- 代价：真实对话片段会发往 DeepSeek，其数据留存与训练条款由用户自行承担；已发出的内容无法撤回。
  豆包与 ChatGPT 对话中可能含第三方信息，策略对此不做区分。Lifebase 不具备网络隔离能力，
  目的地判定依赖插件的 provider 映射。
- 撤销方式：把两个 collector 的取值改回 `local_only`，门禁随即恢复拒绝真实库的 cloud 请求。
