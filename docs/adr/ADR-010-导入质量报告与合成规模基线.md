# ADR-010：导入质量报告与合成规模基线

- 状态：Accepted，用户于 2026-10-05 明确委派实现质量报告与规模测试。
- 日期：2026-10-05

## 决策

1. **Build**：质量报告是派生统计，不更改 canonical v1、Envelope、Parquet schema
   或 RAW。ingest / rebuild 输出单次规范化结果的质量；quality 命令汇总所选成功
   分区，复用 query 的来源和处理版本筛选。
2. **Reuse（Python dataclass / Counter、DuckDB）**：统计身份和内容版本、缺失时间、
   文本/空文本、不支持内容类型和证据数。单次结果使用已有规范化记录；汇总通过
   一次只读 DuckDB 查询按逻辑版本去重，避免重复加载分区。
3. **Build**：报告是数量和能力缺口，不是完整性证明。缺失时间包括 parser 已判为
   不可靠而置空的时间；不支持内容仅指没有内容理解，原始证据仍保留。质量 warning
   不使有效归档或报告返回失败；读取损坏分区仍沿用查询失败行为。
4. **Build**：独立 benchmarks 工具生成确定性的两份重叠 ZIP。包含 5% 新增消息、
   每第 101 条旧消息的版本变化、消息分支、5% 缺失发生时间、10% 缺失记录时间和
   4% 非文本；正文长度可配置。benchmark 不读取真实用户导出。
5. **Reuse（pytest、subprocess、time、resource）**：CI 验证小规模语义、证据与基准
   入口，完整基准由显式命令触发。每档重复测量首次导入、重复导入、聚合查询、
   质量报告；每个阶段启动新进程，生成阶段单独执行。
6. **Build**：保存原始试验数据、耗时中位数、每阶段峰值 RSS、环境/依赖版本、代码
   和 lock 哈希。导出、仓库只留在工具自己创建的临时目录，仓库仅保存统计基线。
7. **Integrate**：没有外部服务。
8. **Defer**：媒体理解、全账户覆盖率推断、真实导出性能报告、跨设备可比的硬指标、
   性能阈值 CI 和未由观测数据支持的存储优化。

## 口径与限制

- missing_* 和内容计数按去重后的内容版本统计；同一消息多个版本可能分别计入。
  单次导入统计不能简单相加得到跨导出的消息数，后者需使用 quality 汇总。
- 空文本为没有字符的 text parts，保留空白字符语义；未知内容类型列为计数分类，
  不把源消息正文、路径内容或媒体标识放进报告。
- 汇总只统计选中的成功分区，不声称不存在失败输入；Source Registry 的失败原因
  继续由 list 查看。不同处理版本默认合并，核对单套处理结果时显式筛选版本。
- elapsed 是库加载之后的操作 wall time，不含启动和数据生成；峰值 RSS 是进程
  的绝对内存峰值，包含库加载，不是净增量。macOS 的 ru_maxrss 字节转 MiB，Linux
  的 KiB 转 MiB；不支持 resource 的平台记为 null，不编造内存结果。
- 基准不清理系统缓存，运行中有共享系统负载影响；单台设备的结果是本地基线，
  不代表真实导出、高媒体占比或更大规模的性能承诺。
- query/quality 当前仍在内存中加载选中的 Parquet 分区，基准包含这部分成本。

## 验收

测试对齐单次与汇总统计，覆盖重叠、版本、不同账户、parser 版本筛选、缺失/异常
时间、空文本、未知内容、空库和损坏文件。生成器验证输出确定性及拒绝覆盖既有
目录；规模样例逐项核对逻辑计数，并由 verify 校验所有证据。
完整基准保存各重复试验，重复导入须不改变持久化文件哈希。
