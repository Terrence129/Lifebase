# ADR-012：来源外发策略

- 状态：Accepted，用户于 2026-10-06 批准。
- 日期：2026-10-06

## 背景

评估「Agent Runtime × Lifebase」构想（用户桌面构想稿，2026-10-06；边界决策见 [ADR-013](ADR-013-Agent运行时集成边界.md)）时发现：未来的查询接口、上下文注入和模型路由都需要回答同一个问题——某条数据能否离开本机、能否发给云端模型。当前 canonical v1 与 Source Registry 都没有这个信息。若等到第一个 agent 集成时再补，已有来源需要逐个回填，新 collector 也容易在接入时遗漏。隐私相关红线以 [AGENTS.md](../../AGENTS.md) §2 为准。

## 决策

1. **Build**：外发策略分三级，按「能否外发」而非「多敏感」定义，消费方可直接执行：
   - `local_only`：只允许本地处理与本地模型；
   - `redact_before_cloud`：脱敏或摘要后才可发送给云端；
   - `cloud_ok`：可直接发送给云端。
2. **Build**：级别类型 `EgressPolicy` 与取值集合 `EGRESS_POLICIES` 定义在 `sync/base.py`；每个 collector 在 `metadata()["egress_policy"]` 声明来源默认值。
3. **Build**：ChatGPT 来源默认 `local_only`。对话虽曾发给 OpenAI，但被重新检索、组合后发给另一家云端模型是新的暴露面，且对话可能提及第三方；放宽需显式配置。
   - 2026-10-06 更新：该默认值由 [ADR-018](ADR-018-聊天来源默认外发策略放宽.md) 放宽为 `cloud_ok`，其余决策继续有效。
   - 2026-10-20 更新：[ADR-020](ADR-020-Harness联调与合成库云端放行.md) 恢复为 `local_only`，并允许全部输入为仓库合成 fixture 的图谱用于云端。
4. **门禁**：`tests/unit/test_registry.py::test_registered_collectors_declare_egress_policy` 要求每个已登记 collector 声明合法级别。
5. **Defer**：执行（查询接口、上下文注入、模型路由按级别拦截或脱敏）、按 source_id 覆盖默认值、逐条记录级别，均待第一个消费方出现时再做。

## 被否方案

- **记录级 `sensitivity` 字段（写入 Evidence / Artifact）**：需修改 canonical v1 schema；当前没有逐条判定的确定性依据，只能由分类器或 LLM 猜测，与「确定性处理先于 LLM」冲突。
- **按敏感程度分级（high / medium / low）**：每个消费方还要自行把级别翻译成行为，同一级别可能被不同消费方解释成不同外发规则。
- **只写 ADR，不改代码**：第二个 collector 接入时没有机械约束提醒声明，容易遗漏。
- **持久化到 registry.sqlite**：策略来自 collector 代码，随版本演进；入库会产生需要迁移的副本，当前无查询需求。

## 后果

- 收益：每个来源从接入起就带外发默认值，未来路由与上下文注入有确定性依据；未改 canonical schema、Parquet 或 Envelope，已有数据无需重建。
- 代价：目前只是声明，没有任何代码读取并执行它；在执行层落地前，它不提供实际保护。
- 粒度是来源类型级：同一来源中较不敏感的内容也按来源默认值处理，宁严勿宽。
