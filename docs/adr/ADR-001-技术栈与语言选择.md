# ADR-001：技术栈与语言选择

- 状态：Accepted
- 日期：2026-10-05

## 决策

1. 主语言 **Python ≥ 3.12**，依赖管理用 `uv`，src layout（`src/lifebase/`）。
2. MVP 数据栈：**本地文件系统 + 内容寻址对象存储 + Parquet + DuckDB + SQLite**。
3. 仓库形态：**单 monorepo**（四层以子包 `sync/` `vault/` `graph/` `humanos/` 分隔）。
4. 备份复用 **restic**，不自研加密/备份层。

## 理由

- 计划复用/借鉴的开源组件（HPI、ActivityWatch、Dawarich 等）几乎全部是 Python 生态，可以直接借代码而非重写。
- 数据栈满足 local-first、可移植、便宜、分析查询强、schema 迭代容易（docs/context.md §19–20）。
- 单人开发下 monorepo 跨组件重构成本最低；目录已是独立包，未来若独立开源某组件只需机械拆分。
- PostgreSQL/pgvector 等留到 HumanOS Web 应用需要事务状态与向量检索时再引入（Defer）。

## 明确不做（Defer）

- Neo4j / Milvus / Weaviate / Qdrant —— 不为「可能以后需要」提前引入。
- 自研备份系统。
- 云端基础设施、移动端、UI 打磨。
