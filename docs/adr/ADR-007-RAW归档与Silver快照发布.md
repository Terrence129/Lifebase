# ADR-007：RAW 归档与 Silver 快照发布

- 状态：Accepted
- 日期：2026-10-05

## 决策

1. **Build**：RAW 流式复制并计算 SHA-256，写完、fsync 后以硬链接原子发布到内容
   地址。已有对象只读回校验，损坏时报告，不能靠覆盖来修复。
2. **Reuse（SQLite / Python 标准库）**：RAW manifest 以 `(source, content_hash)`
   唯一键只追加，保存首次入库时间；另一个 Source Registry 数据库保存可更新的
   导入结果、错误、来源时间范围与成功分区。两者职责分开。
3. **Build**：编排先归档 RAW，再解析归档对象、规范化、发布 Silver，最后登记
   成功分区。解析或写入失败保留 RAW；下次重复导入可重试。
4. **Reuse（PyArrow / Parquet）**：每个来源、RAW 哈希、collector/parser/schema
   版本组合生成一个分区。三张表和校验元数据先写进临时目录，再原子发布整目录。
   已存在的分区校验后复用，不原地改写。
5. **Reuse（DuckDB）**：只查询登记成功的分区，按完整逻辑行去重。相同身份及版本
   的内容可跨分区复用；各 RAW 对应的 Evidence 保留。查询经过 Arrow 返回结果，
   时间统一为 UTC，不新增 pytz。对用户 SQL 禁用外部访问及扩展自动安装。
6. **Integrate**：本轮不引入外部服务。
7. **Defer**：后台监听、跨平台文件监视、全量媒体理解、Silver 压实与流式大规模查询。

## 理由与代价

- 三张独立文件逐一替换会暴露不完整快照；目录发布使查询只看到完整的已登记分区。
- 内容可能重复存在于多个物理 Parquet 分区，换取简单、可重试的写入机制；逻辑查询
  去重，RAW 对象按哈希仅保留一份。
- 当前 DuckDB 查询先将分区载入 Arrow 内存表，适合原型；大规模查询方式另行演进。
- JSON 成员处理上限为 128 MiB；ZIP 的其他成员不解压，整个 ZIP 仍完整保存。
- 源错误、RAW 损坏及派生文件损坏明确报告；对已发布文件不会静默替换或跳过。
- 数据目录拒绝位于 Git 工作树中。新建数据目录私有，RAW 对象发布为仅所有者可读；
  不修改用户已有目录的权限。

验收包括 RAW 哈希读回、十次导入文件哈希不变、跨快照版本和证据、导入顺序、
写入失败重试、来源账户隔离、SQL 只读访问，以及三个 CLI 命令。
真实官方导出尚在生成，本轮仅使用合成数据验证。
