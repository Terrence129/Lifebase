# ADR-017：独立私有数据仓库与无损迁移

- 状态：Accepted，用户于 2026-10-06 明确授权迁移、提交与推送独立 private 数据仓库。
- 日期：2026-10-06

## 背景

用户要求先提交代码仓库的现有改动，再将真实库与演示库迁入独立的 Lifebase-data
仓库，并整理既有来源导出供长期维护。原路径检查拒绝所有 Git 工作树；一个 RAW
对象超过普通 GitHub 单文件上限。此次范围不同于已撤销的代码仓库 devdata 例外
（[ADR-003](ADR-003-开发数据例外.md)）；当前约束见 [AGENTS.md](../../AGENTS.md)。

## 决策

- **Reuse（Git / Git LFS）**：Git 管理目录、索引及维护文档，LFS 管理来源导出、
  RAW、Parquet 和 SQLite 的版本内容。LFS clean 只生成 Git 指针，不改工作树数据。
- **Build**：独立数据仓库根的 `.lifebase-data.json` 明确声明用途、版本、私有目的地、
  origin 身份和库根。路径检查只接受配置与实际 origin 一致的登记库根，普通代码
  仓库、exports 和未登记子目录仍被拒绝；本地声明不证明远端仍为 private。
- **Build**：目录为 `exports/<来源>/<导出日期>/`、`libraries/personal/`、
  `libraries/demo/`、`maintenance/`、`bin/` 和 `scripts/`。导出保持原结构，两个库
  保持原内部布局与快照身份，不改 canonical v1 / Envelope。
- **Reuse（文件系统 rename、现有 verify / graph status）**：同盘重命名保留文件字节、
  权限和修改时间，以迁移前后逐文件 SHA-256 及完整性检查验收。旧路径作为兼容
  链接保留；迁移报告留在私有仓库。
- **Build**：维护入口固定库选择，提交前检查数据库静止、内容哈希、来源证据、Gold
  和 LFS 指针，推送前核对指定远端身份及可见性。多设备 clone 后先 hydrate LFS，
  再恢复 RAW 只读权限；Git 本身不保存 Unix 权限或原修改时间。
- **Integrate**：GitHub 私有远端承担本次明确授权的数据同步；collector 的模型目的地
  策略保持原语义，不因数据同步而改为 cloud_ok。
- **Defer**：独立备份恢复仍按 restic 决策另行验收；此次不做 Harness 或模型联调。

## 被否方案

- 将数据加入代码仓库：混合了代码发布与个人数据同步的权限和历史。
- 无条件取消 Git 路径门禁：不能限制此次批准的范围。
- 普通 Git 保存所有大文件：当前 RAW 已超过 GitHub 上限，二进制增长也不便维护。
- 在迁移时重新导入或重建所有数据：会改变处理时间或派生身份，没有迁移必要性。
- 为清理警告而删除 Finder 文件或旧快照：它们保持原状，忽略规则仅控制后续提交。

## 后果

代码仓库仍可独立运行合成测试，私有数据仓库可在不同设备以固定结构恢复。Git/LFS
同步带来远端数据暴露、存储和下载成本；迁移中的字节、权限与时间保真不意味着
未来 clone 自动恢复这些元数据。长期维护须将应用写入与 Git 同步错开，并持续核对
私有可见性。使用方式见 [数据仓库说明](../data-repository.md)。
