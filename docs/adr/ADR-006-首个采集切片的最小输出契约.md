# ADR-006：首个采集切片的最小输出契约

- 状态：Accepted，用户于 2026-10-05 明确批准按草案实现。
- 日期：2026-10-05

## 背景

开发环境已验证，下一步是为 ChatGPT 官方导出的首个垂直切片准备合成输入，
并在实现前审阅最小输出契约。

## 决策

1. **Build**：来源映射采用平台无关的 Event（会话）、Artifact（消息）、Evidence
   （来源引用）三张表。逻辑输出包保留现有 Envelope，物理上将它保存在 Evidence
   中，以支持同一内容版本关联多个 RAW 出处。
2. **Build**：以来源账户和源 ID 确定身份，以规范化 payload 哈希确定内容版本；
   不同来源 ID 的相同正文仍是不同消息，相同 ID 的不同正文保留多个版本。
3. **Build**：保留消息分支，采用 ZIP 哈希、成员名及 JSON Pointer 定位原始证据。
   known_at 表达来源版本的记录时间，时间不明不补造。
4. **Reuse**：已有 Envelope、Python 标准库、PyArrow / Parquet 与 DuckDB，
   无需新增第三方依赖。
5. **Integrate**：本轮不引入外部服务。
6. **Defer**：媒体理解、图谱与 AI 推断；正式 schema 与解析器已在本切片实现。

## 理由与代价

- 三张表让跨导出复用消息内容和新增来源证据分开处理；独立 Evidence 表增加一次
  关联查询，但不会为了去重丢失 RAW 位置。
- 版本保留避免用导入顺序覆盖历史；本轮查询可能返回多个版本，默认视图选择
  留到有明确产品需求时再定。
- 合成输入覆盖重叠导出、节点与消息 ID 不同、分支、时间缺失及内容冲突。
- 已落地 dataclass、JSON Schema、RAW 归档与 collector；由合成端到端测试验证。
