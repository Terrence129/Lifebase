# ADR-022：会话列表工具与分页

- 状态：Accepted，用户于 2026-10-21 批准范围、标题外发与 timeline 分页。
- 日期：2026-10-21

## 背景

[ADR-016](ADR-016-聊天图谱与Harness就绪接口.md) 的五个只读工具没有会话级入口。真实库试运行中，
模型只能靠多轮关键词搜索摸索全库，单题最高约 136K token；search 与 timeline 都没有分页参数，
超出 limit 的命中无法读取。项目约束见 [AGENTS.md](../../AGENTS.md)。

## 决策

- **Build（conversations）**：HumanOS 新增只读工具 `conversations`，CLI 同名子命令。每条返回
  conversation_id、来源、标题（最多 80 字，标注是否截断）、首末消息时间、按身份计的消息数与用户
  消息数、按 TF-IDF 权重之和取前五个主题、标题版本的 evidence_ids、标题版本冲突标记。不返回消息正文。
- **Build（排序与筛选）**：按最近消息时间倒序，没有带时间消息的会话排在最后。支持 `--source`、
  `--since`/`--until`（选取范围内有消息的会话）、`--limit`（1–100）、`--offset`（0–1,000,000）。
  data 返回 total、offset、next_offset；还有下一页时附 RESULTS_TRUNCATED。
- **Build（timeline 分页）**：timeline 增加 `--offset`，data 增加 offset 与 next_offset。
  search 与 context 不变。
- **Build（体积）**：列表只给 evidence_id，完整定位经 `evidence` 工具读取。同样 100 个会话，
  完整定位约 12.3 万字符，只给 ID 约 5 万字符。
- **Build（契约）**：`schemas/humanos-api-v1.json` 新增 conversations 工具与 conversation 定义，
  均为新增字段，api_version 保持 1。不改 canonical schema，不重建图谱，快照身份不变。
- **外发**：标题与正文同受来源策略门禁约束；用户批准标题随结果发往已批准的云端目的地。
- **Integrate**：Harness fork 的 `lifebase-plugin/` 注册 `lifebase_conversations`，timeline 透传
  offset，引用收集同时识别 evidence_ids。
- **Defer**：按标题或语义搜索会话、会话摘要（需模型生成，属于 Gold 断言）、search 分页。

## 被否方案

- 列表附完整 evidence 定位：每个会话多约 700 字符，与减少 token 的目标冲突。
- 在 search 上加分页代替会话列表：模型仍需猜关键词，无法知道库里有哪些会话。
- 由模型生成会话摘要：摘要属于 AI 推断，按 AGENTS.md 只能作为带证据的 Gold 断言，需另定保存格式。

## 后果

- 收益：每页最多 100 个会话，少量调用即可列完全库；长会话可以分页读全。
- 代价：标题可能概括敏感内容，随结果外发；主题词是统计关键词，不代表会话主旨。
- 消息数按身份计，与 search.total 的版本计数口径不同，接口说明已注明。
