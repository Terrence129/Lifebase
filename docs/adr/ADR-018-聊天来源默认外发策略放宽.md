# ADR-018：聊天来源默认外发策略放宽

- 状态：Superseded，由 [ADR-020](ADR-020-Harness联调与合成库云端放行.md) 取代；2026-10-20 聊天来源恢复为 `local_only`。
  原状态：Accepted，用户于 2026-10-06 批准放宽范围与机制，代码与文档同日落地。
- 日期：2026-10-06

## 背景

双来源聊天图谱与 HumanOS 只读工具已经交付，项目停在 Harness 联调交接点（见
[ADR-016](ADR-016-聊天图谱与Harness就绪接口.md) 与 [当前阶段](../reference.md)）。
运行时候选为本地 DeepSeek Harness fork，用户已在其仓库配置 DeepSeek API，模型路由为云端。

[ADR-012](ADR-012-来源外发策略.md) 决定聊天类来源默认 `local_only`：对话被重新检索、
组合后交给另一家云端模型构成新的外发面，且对话内容包含对方的消息。该默认值由 collector
的 `metadata()` 声明，在 `humanos/policy.py` 执行，且没有覆盖入口。

后果是云端模型取不到任何查询结果：目的地为 cloud 时门禁要求整份图谱的输入来源全部为
`cloud_ok`，两个聊天 collector 都声明 `local_only`，请求一律以 `EGRESS_BLOCKED` 拒绝，
合成库与真实库同样如此，Harness 联调无法开始。

用户决定放宽：允许 DeepSeek 读取，范围覆盖合成演示库与真实个人库。

## 决策

`chatgpt` 与 `doubao` 两个 collector 的 `metadata()["egress_policy"]` 由 `local_only`
改为 `cloud_ok`，即来源类型级默认值放宽到云端可用，覆盖 `chatgpt:personal`、
`doubao:personal`、`chatgpt:synthetic-account` 与 `doubao:synthetic-account`。

策略在查询时从 collector 元信息实时读取，不写入来源登记表或图谱快照，因此既有库不需要
重新导入或重新构图，改动即时生效。

门禁逻辑本身不变：cloud 仍要求整份快照的输入来源全部为 `cloud_ok`，来源筛选不能绕过；
未知策略与没有脱敏器的 `redact_before_cloud` 继续拒绝。

撤销方式是把取值改回 `local_only`，门禁随即恢复拒绝；已经发送给云端的内容无法撤回。

本 ADR 取代 [ADR-012](ADR-012-来源外发策略.md) 决策 3 中「ChatGPT 来源默认
`local_only`」的部分；三级取值、由 collector 声明、由查询接口执行的整体框架继续有效。

## 被否方案

- **数据仓库内的覆盖配置**：在私有数据仓库声明哪些来源可用云端，按来源名精确开关，
  配置不进公开代码。被否：用户选择直接调整默认值，接受其全局生效。
- **每次查询显式开关**：CLI 增加覆盖参数，逐次授权。被否：授权不落地，插件一旦把该参数
  写死，效果与默认放宽相同，却多出容易误用的一层接口。
- **`redact_before_cloud`**：先脱敏或摘要再外发。被否：当前没有脱敏器，门禁在没有脱敏器
  时一律拒绝；实现成本远高于本次目标。
- **保持 `local_only`、改用本地推理服务**：被否：用户已配置云端 API，选择先以云端模型
  推进联调，本地模型留待后续评估。

## 后果

收益：云端模型可以直接消费五个只读查询接口，Harness 联调得以开始；合成库与真实库行为
一致，不需要按库维护分支。

代价：

- 默认值写在公开代码里，全局且长期生效。任何能调用 CLI 的一方只要声明 cloud，就能取得
  查询命中的原文片段，不区分库，也不区分合成与真实。
- 真实个人库的对话内容会经 DeepSeek API 离开本机。外发量由查询驱动且有上界：`search`
  单次最多 100 条、每条 300 字片段，`context` 最多 10 条、正文合计 3000 字，`evidence`
  只读 Silver，不读也不返回 RAW 字节。它不是全库外发，但仍包含对方的消息。
- 内容发出后即离开本地控制，云端可能留存或缓存，撤销策略收不回已发送的内容。
- 失去按来源或按库细分开关的能力：日后若需要「合成放行、真实拒绝」，必须重新引入
  覆盖机制。
- 受影响的门禁测试与文档需同步改写。
