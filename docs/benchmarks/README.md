# 合成导出规模基线

测量日期：2026-10-05。原始数据与每次试验结果保存在
[quality-scale-baseline.json](quality-scale-baseline.json)。所有输入由生成器构造，不含真实导出。

## 测量方法

```bash
conda activate lifebase
uv run python -m benchmarks.run --sizes 1000 10000 50000 --repeats 3 --output docs/benchmarks/quality-scale-baseline.json
```

- 每档生成 A / B 两份 ZIP；B 包含全部 A 消息，新增 5%，修改每第 101 条旧消息。
  每会话最多 50 条消息，包含回复分支；每第 20 条缺失发生时间，每第 10 条缺失
  记录时间，每第 25 条为非文本。编辑版本有可靠更新时间，旧的未知时间仍保留。
- 正文生成参数为 256 字符，另有合成消息编号和编辑标记。ZIP 不压缩，元数据固定；
  消息身份、时间、内容、顺序和预期计数可复现。
- 每档重复 3 次，每次使用新的仓库。分别测量 A+B 首次导入、A+B 重复导入、
  `count(DISTINCT record_id), count(*)` 聚合查询、quality 汇总。
- 生成过程和每个测量阶段都使用独立进程；数据生成不计入指标。耗时为加载库之后
  的操作 wall time，统计中位数；内存为绝对进程峰值 RSS，包含 Python 与库加载，
  每阶段取三次最大值。macOS / Linux 使用标准库 resource；不支持的平台记 null。
- 不主动清理系统缓存，没有声称冷启动。指标也不包括命令启动时间或完整正文导出
  的输出序列化开销。运行中的系统负载与磁盘、库版本均会影响结果。
- 校验身份、版本、证据数量；重复导入校验持久化文件哈希不变。全部输入和数据仓库
  位于基准自己的临时目录，退出时清理；持久化的 JSON 只有统计和环境信息。

本次环境：Python 3.12.15，DuckDB 1.5.6，PyArrow 25.0.1，Darwin 27.0.0 / arm64，
6 个逻辑 CPU。JSON 中的 git_head 是当时的提交基点，source_sha256 标识测量时的
工作区应用与基准代码；本次测量包含尚未提交的实现，不能仅凭 git_head 复现。

## 当前含义

- 这三档合成输入的身份、版本、证据与质量统计均符合预期。它们验证了当前链路在
  这些规模和内容分布下的行为；官方真实导出的兼容性仍需单独本地验收。
- 重复导入仍校验 RAW、重新解析并比较现有 Parquet 的逻辑内容，所以耗时接近
  首次导入。当前机制优先检测同版本处理结果变化，幂等不等于跳过处理。
- query / quality 会将全部选中分区载入内存并去重，内存成本随规模增加。聚合查询
  输出很小，但载入成本仍在；全文输出、更长正文、更多快照和媒体分布未由本表覆盖。
- 基线用于后续改动前后比较，不设性能承诺。CI 只运行小规模正确性与命令入口检查，
  不运行完整基准或机器相关的时间阈值。
